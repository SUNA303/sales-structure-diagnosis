# 調査の設計：何を決めるために・どこを・どこまで調べるか

目的は「全部調べる」ことでも「大量に集める」ことでもなく、**砂川さんがクライアントと「次に何を試すか」を決められるところまで、提案を変えうることを確かめきる**こと。
最初から全員に同じサイトを調べない。決めることと、お客さんが実際に知り・比べ・買う経路に合わせて調査先を選ぶ。

## 1. 今回決めることを選ぶ
次から、今回の相談で決めることを選ぶ。依頼に指定があればそれを主にする。指定が無い集客の相談は「集客経路」を主にする。主は1つ、提案を左右する時だけ従を1〜2つ足す。

| 決めること | 本スキルで出すもの | 設計の正本（本スキルは材料を渡す） |
|---|---|---|
| 集客経路 | 主軸・新規の入口・補助・今はやらない | 本スキル |
| 販売導線（入口→相談・体験→申込み→2回目・継続） | 市場の導線の型と、本人に合う導線の案 | 文面・台本は sales-skill／salesline-skill |
| 訴求（誰の・どの悩みや願望に呼びかけるか） | 市場で使われている切り口と、空いている切り口 | 文面は neora、コンセプトは concepy-product-architect |
| 対象顧客 | 買っている人・探している人の像と、その根拠 | concepy-product-architect／category-of-one |
| 商品の入口・提供形式 | 市場で選ばれている入口（無料相談・診断・単発・講座など）と形式 | concepy-product-architect／course-business-design |
| 価格帯 | 相場と、本人の価格が通るかの見立て | concepy-product-architect |
| 差別化の方向 | 価格帯での位置・打ち出しの空白・本人にしか言えないこと | category-of-one |

枠に上限がある人（施術・個別セッション）は、新規を増やす前に「初回から2回目への流れ」が結論を左右することが多い。再来の割合が分からなければ、まずそれを数えることを試しに入れる。
各決めることに今の仮説と「これが違ったら何が変わるか」を置く（内部の設計用。成果物には「調べて見立てが変わった点」だけ書く）。

## 2. お客さんが買うまでの経路を仮説にする
「知る → 比べる → 申し込む」のそれぞれで、対象のお客さんが実際に使っていそうな経路を置く。
例：地域検索・地図／SNS／広告／予約・販売サイト（ココナラ・ストアカ・ホットペッパー等）／講座・セミナーサイト／紹介・口コミ／法人の発注（公募・比較サイト・紹介）

## 3. 経路に合う情報源を選び、理由を書く
仮説の経路ごとに、確かめられる情報源を選ぶ。**選んだ理由**（どの経路・どの決めることを確かめるためか）を成果物に1行ずつ残す。
情報源の一覧 → research-sources.md／広告と遷移先の見方 → ad-funnel-research.md

### 型ごとの優先の例（固定のメニューではない。選ぶための例）
| 型 | 優先しやすい情報源 |
|---|---|
| 地域の整体・サロン・教室 | 広告と遷移先（出している競合がいれば）、商圏内のGoogle検索・マップと口コミ、予約ポータル、既存客が予約・再来店した理由 |
| オンラインのコーチ・講師・コンサル | 広告と販売導線、講座・サービスサイト（ココナラ・ストアカ・MOSH等）と受講者レビュー、SNS上の見込み客の言葉 |
| 法人向けの個人事業 | 広告の有無、発注者・決裁者、募集要項・公募、導入事例、紹介経路、商談で求められる根拠 |

**広告と遷移先は業種を問わず有無を確認する**（数分で済む）。広告を出している競合がいれば優先して読む。出していない市場・紹介が主の市場では深掘りしない。
自社データ（相談・成約・失注の記録、既存客の声）は、あればどの型でも最優先で読む。

## 4. 基本の項目（ほぼ毎回）
1. 競合の数と価格帯
2. お客さんが何で探し、何で決めるか（調査データ）
3. 売れている人・店の入口と販売導線
4. 広告の有無と、広告から先の導線（有れば ad-funnel-research.md で深掘り）
5. そのジャンルでSNSが効くか（後から始めて伸びた人の有無）
6. 見込み客の居場所と、悩みの言葉
7. **代替手段**：競合だけでなく、お客さんが同じ悩みに対して選んでいる別の手段（例：整体なら整形外科・セルフケア動画・マッサージチェーン、コーチなら本・無料動画・友人への相談、研修なら社内研修・eラーニング）。価格と「なぜそちらを選ぶか」

## 5. 仮説によって足す項目（提案を変えうる時だけ）
| 足す項目 | 足す時 |
|---|---|
| 市場が伸びているか・縮んでいるか | 新しい分野に出る時、競合が急に増えた・減った時 |
| 季節・時期の波 | 繁忙期と閑散期がある業種 |
| お客さんの予算感・払っている金額 | 価格が相場から外れている時、価格が未定の時 |
| 業種の規制・表現のルール | 健康・美容・お金・資格が絡む時 |
| プラットフォームの規約・手数料 | ポータル・スキル市場・広告を候補にする時 |
| 地域の人口・対象の人数 | 地域型で、対象をかなり絞る時 |
| 他人の導線（講座・コミュニティ・団体） | 本人に「借りる」候補がありそうな時 |
| 海外の事例 | 日本に例が少ない時。使う時は日本の顧客行動・価格・商習慣に合うかを別に確かめる |

### 外してよい項目
答えがどちらでも今回決めることが変わらないものは調べない。外した項目は内部メモに理由を残す。

## 6. 深さの基準
- 競合：上位10〜20件を表にする。「上位」の取り方と列は型で変える
  - 地域型：ポータルの表示順・口コミ数の多い順。列＝名前・価格・対象・打ち出し・口コミ数・入口
  - オンライン個人向け型：スキル市場の販売数順、または検索上位のLP。列＝名前・価格・呼びかけ・入口・証拠の見せ方
  - 法人向け型：比較・紹介記事と検索上位。列＝名前・打ち出し・価格の目安・対象業種・実績の見せ方
- 提案を左右する数字：出典2つで確かめる（例外は research-rules.md）
- 仮説と違う情報が出たら、そこをさらに1〜2段掘る（なぜ違うのか・本人にも当てはまるのか）
- 情報源同士が食い違ったら、都合のよい方だけを採らず両方を書く

## 7. 終わりの基準
次がそろったら調べ終える。件数ではなく、次に試すことが決められるかで判断する。
- 今回決めることそれぞれに、理由になる事実がある
- 直近で調べた2〜3件が、提案を変えなかった
- 調べられなかったことは「言えないこと」「確認したいこと」に入り、それ次第で何が変わるかが書けている

## 8. 手分け（項目が多い案件）
手分けできる環境では、項目ごとに担当を分けて同時に調べる。担当には「調べる項目・仮説・深さの基準・返す形（事実／推論の区別・URL・確認日）」を渡す。集まった結果をまとめてから、別の目で確かめ直す。

## 9. 商談前の簡易版（体験セッションの前に、見込み客について調べる時）
consulting-skill の「商談前の見立て」（references/16）の材料として使う。見込みのある人（2ステップで GREEN）だけに行い、深い調査は契約後に回す。
- 決めること：「本人が言う詰まりが、市場から見てもそこか」と「どのコースのどの中身が当たるか」の2つ
- 調べる項目：基本の項目のうち、詰まりに関係する3つまで（多くは 競合と価格帯／お客さんの探し方／代替手段）＋本人の掲載情報
- 深さ：提案を左右する数字だけ出典2つ。競合表は5件前後でよい
- 出すもの：相手に見せてよい【事実】の一文を3つまで（出典・確認日つき）。切り返しの材料になる事実はこの3つとは別枠で1〜2つ。信頼できる出典が無ければ探し続けず、本人の数字（続けた期間と結果など）で代える。試しの設計・競合の全表は作らない（契約後）
