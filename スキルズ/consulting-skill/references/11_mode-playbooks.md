# §7 各モードの進行ステップ
> 本体SKILL.md v1.5.0 から**原文コピーで移設**（2026-07-03・v2.0.0分割。要約・改変なし）。

## §0 モード判定の起動キーワード（本体§5から原文移設）

【モード1】診断モード（diagnose）★最頻出・最重要
キーワード：「うまくいってない」「何が問題か見て」「現状を整理して」
　　　　　　「このクライアントを診断」「どこが詰まってるか」
→ 思考OS（§3）→ 顧客の旅の地図（§4B）で詰まりの段を特定

【モード2】設計モード（design）
キーワード：「設計して」「組み立てて」「立ち位置を作りたい」
　　　　　　「発信を設計」「オファーを作りたい」「コース設計」
→ 診断で特定した段に対応する層で、具体的な設計を作る

【モード3】レビューモード（review）
キーワード：「この投稿どう？」「このLP見て」「この施策レビュー」
　　　　　　「今やってることを評価して」
→ 既存施策を6レイヤー／顧客の旅に照らして点検・改善案を出す

【モード4】壁打ちモード（roleplay）
キーワード：「壁打ち」「相談に乗って」「考えを整理したい」
　　　　　　「クライアント役やって」「想定問答」
→ 砂川さんの思考整理／クライアント役の演技／想定問答の練習

【モード5】初回セッションモード（onboarding）
キーワード：「初回セッション」「キックオフ」「契約後の最初」
　　　　　　「オリエン」「最初の面談の型」
→ 契約直後の初回コンサルセッションを標準フローで進行

【モード6】マッチングモード（matching）★(A)惹き寄せ＋(B)見極め
キーワード：「価値を求める人と出会いたい」「来た人を見極めたい」
　　　　　　「診断フォーム」「事前アンケート」「トライアルにつなげたい」
　　　　　　「集客で消耗している」「冷やかし・準備不足の人が多い」
→ §6「マッチング機能」で、入口の自己選択トリガー（A）と見極め診断（B）を設計・運用する
　 （診断フォーム/相談スクリプト/倫理の実物は Premium Match 資産 04/06/10/ethical を参照）


## 7. 各モードの進行ステップ（現場で開いてそのまま進める）

### モード1：診断モード（diagnose）★最重要

**目的**：クライアントの売上構造の「詰まりの段」を特定し、最上流の一手を返す。

```
Step1：現象を聞く（共感型で）
  「今いちばん困っていることは？」「それはいつ頃から？」
  → 努力を肯定しながら聞く（全否定しない）
  → 規模ステージ（S0ゼロイチ〜S5億円）を事実で判定する（references/20 §1）。
    S0は3レバーで割らず「聞いた・払った」の数、S4〜S5は商品ライン別＋粗利・回収期間で見る

Step2：思考OSで論点に変換する（§3）
  ・現象と論点を区別（論点思考）
  ・奥のジョブ＝進歩を見抜く（機能/感情/社会の3層）
  ・プロービング：「もしかして◯◯では？」と仮説をぶつけ反応で確定

Step3：顧客の旅の地図で詰まりの段を特定する（§4B）
  ①立ち位置／②物語/③発信/④期待醸成/★オファー/⑥成約/⑦関係維持
  → 「最上流の詰まり」を見つける（下流だけ直しても空回りする）

Step4：早見表で一手に変換する（§6）
  → 詰まりの段に対応する層の知見を引く
  → 「よい仮説の2条件」で自己チェック（掘下げ済み？即実行可能？）

Step5：伴走の言葉で返す
  「あなたはここまで◯◯で成果を出してきた。
   ただ、本当の詰まりは△△の段にあります。
   なので、まず明日□□をやってみましょう。3日後に反応を一緒に見ます」
```

**診断モードの出力フォーマット**：
```
【現象（本人が言っていること）】
【真の論点（現象を変換した結果）】
【奥のジョブ（機能/感情/社会）】
【詰まりの段（顧客の旅の①〜⑦のどこか）】
【引く知見（層・出典）】
【次の一手（明日できる具体行動）】
【伴走の次のチェックポイント（いつ・何を見るか）】
【推奨コース判定（§10）】
```

### モード2：設計モード（design）

**目的**：診断で特定した段を、具体的な設計に落とす。

```
Step1：どの段の設計かを確認する（診断結果を引き継ぐ）
Step2：その段の層の知見を「設計手順」として展開する
  例）①立ち位置の設計：
     ・ブランド・ビジョン・モデル（6〜12要素を出す→コア2〜5を選ぶ）（ブランド論第3章）
     ・自分専用の細いはしごを定義（ポジショニング）
     ・3円ベン図（得意×市場が求める×成長余地）でワン・コンセプトを絞る（ブレイクスルー第5章）
  例）★オファーの設計：
     ・価値方程式で4変数を点検 → 問題リスト → 解決リスト → トリム&スタック（$100M Offers）
     ※新商品そのものの企画・コピー清書は concepy へ連携（§9）
Step3：「よい仮説の2条件」で点検し、即実行できる形に落とす
Step4：実行の順番と最初の一歩を明示する
```

**設計モードの出力フォーマット**：
```
【設計する段】
【設計の骨子（引いた知見と、その砂川流の落とし込み）】
【具体アウトプット（投稿の型／オファーの構成／コース設計など）】
【実行順序（何から・いつ）】
【concepy / market-research 連携の要否】
```

### モード3：レビューモード（review）

**目的**：既存施策（投稿・LP・コース・発信戦略）を点検し、改善案を出す。

```
Step1：レビュー対象を6レイヤー／顧客の旅のどの段のものか分類する
Step2：その段の「合格基準」に照らして点検する
  ・①立ち位置：ウリは1つに絞れているか／比較対象外になっているか
  ・③発信：一文目で掴めるか／resonateしているか／感情が動くか／コンセプトを売れているか
  ・★オファー：価値方程式の分母が削れているか／特典で価値を積めているか
  ・⑦関係維持：ランク別の設計があるか／共感→共震→共有になっているか
Step3：「先に不安を言葉にしてから応える」（コピーDC-10反面教師）トーンで改善案を出す
Step4：直す優先順位を1つに絞って返す（あれもこれも言わない）
```

**レビューモードの出力フォーマット**：
```
【対象（どの段の施策か）】
【良い点（必ず先に肯定する）】
【最も効く改善点（1つに絞る）】
【改善後の具体例】
【次に見るべき指標】
```

### モード4：壁打ちモード（roleplay）

**目的**：砂川さんの思考整理／クライアント役の演技／想定問答の練習。

```
3つの使い方：

(a) 思考整理の壁打ち
  砂川さんの考えを、思考OS（なぜ5回／両極端／反対側から）で揺さぶり整理する。

(b) クライアント役の演技
  本Skillがクライアントを演じ、砂川さんがコンサル役を練習する。
  難易度Lv1（素直）〜Lv5（疑い深い/答え合わせタイプ）を設定。
  ※sales-skillのロープレ（成約練習）と棲み分け：
    こちらは「診断・伴走の練習」、sales-skillは「成約の練習」。

(c) 想定問答
  「クライアントにこう言われたらどう返す？」をシミュレートする。

開始時に確認：
  ・どの使い方か（a/b/c）
  ・(b)なら：クライアント像・難易度・想定場面
```

### モード5：初回セッションモード（onboarding）

**目的**：契約直後の初回コンサルセッションを標準フローで進行する。

```
Step1：関係の土台（共感型で安心を作る）
  「契約ありがとうございます。まず一緒に現在地を整理させてください」

Step2：現在地の全体診断（診断モードの圧縮版）
  ・顧客の旅①〜⑦のどの段にいるか
  ・努力依存 vs 構造設計のどちら寄りか

Step3：ゴールの言語化（ジョブ理論で奥の進歩まで）
  ・機能（売上）／感情（不安からの解放）／社会（どう見られたいか）

Step4：「どのLTVの顔の話か」を最初に揃える（LTV最大化第1章）
  ・KPI／投資判断／理念／現場活動 のどの話をしているか合わせる
  → 砂川さんとクライアントのズレを初回で解消する

Step5：3ヶ月/6ヶ月/12ヶ月の伴走ロードマップを置く（コース別）
  ・90日行動計画（ブレイクスルー第5章）：30/60/90日に分解
  ・各中間目標に【成果物・指標・時間軸】

Step6：最初の一歩を1つだけ決めて終わる（保留で終わらせない）
```

### モード6：マッチングモード（matching）★(A)惹き寄せ＋(B)見極め

**目的**：価値を求める人と自然に出会い（A）、来た人が「今その段階か」を見極め（B）、低リスクのトライアル・成約（sales-skill）へ渡す。

```
[(A)惹き寄せ側]
Step1：今どこが詰まっているか分ける（探し回る消耗＝(A)不足／冷やかし多い＝(B)不足）
Step2：宛先テクスチャを決める（(a)努力に疲れた人／(b)特殊だと思う質重視／(c)決断回避）
Step3：入口の一文を作る＝共通の入口の約束〈即決させない・リスクは私が外す・一人にしない〉を主役に、
       テクスチャ宛ての発見の一文を添える（§6(A)）。煽らず・行動で名指す（「まず小さく試せる」）
Step4：実装先を1つ決める（発信冒頭／LP冒頭／2ステップアンケートの入口）
  ※入口の一文の清書を“商品レベル”で作り込むときだけ concepy 連携（§9）。通常は本体内で完結

[(B)見極め側]
Step5：事前アンケート（資産06・7問14点）で適合を判定する
  ・過去事実 vs 未来発言（Mom Test）／3通貨が動いているか
Step6：個別相談（資産10・60分5段階）で、信頼を立てながら適合を一緒に確認する
  ・自己志向を下げる（Trusted Advisor）／価値が立つ前にオファーを出さない（SPIN）
  ・抵抗（ANXIETY/HABIT）は潰さず情報として扱う（ジョブ理論）
Step7：低リスクのトライアルに渡す（即決を迫らない）→ 成約は sales-skill 領域
```

**マッチングモードの出力フォーマット**：
```
【詰まり（(A)惹き寄せ不足／(B)見極め不足のどちらか）】
【宛先テクスチャ（a/b/c）】
【入口の一文（共通の約束＋テクスチャ宛て）】
【実装先（発信/LP/アンケート入口）】
【(B)見極めの次の一歩（アンケート/相談のどこを直すか）】
【sales-skill / concepy 連携の要否】
```
